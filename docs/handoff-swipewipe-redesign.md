## Gotchas

- **No XCTest target exists in this project** (confirmed via `project.yml`) — don't add one mid-implementation; manual on-device testing is the intended verification method throughout (see the plan's Assumptions for why).
- **`.team-id`** (gitignored) must contain the Apple Developer Team ID for `build-ipa.sh` to work. It already exists on this Mac (`7A98LKSLC3`) but won't exist in a fresh environment or worktree — if the script errors with "No .team-id file found", open the project in Xcode once, set the Team under Signing & Capabilities for both targets, then follow the script's own error message.
- **Confirmed in this worktree:** `.team-id` is per-worktree (gitignored, so a fresh `git worktree add` doesn't carry it over) — copied it in from the main checkout. A plain `xcodebuild build` (no team override) fails with "Signing ... requires a development team"; `build-ipa.sh` handles this itself, but an ad-hoc `xcodegen && xcodebuild build` compile-check (as the plan's Verification Contract literally shows) needs `DEVELOPMENT_TEAM="$(cat .team-id | tr -d '[:space:]')" -allowProvisioningUpdates` appended, same as `build-ipa.sh` does internally.
- **`SwipeSession` is `@MainActor`**, but `reload()` dispatches the actual `PHAsset` query to `Task.detached` off the main actor. Its static query helpers (`query(for:)`, `bookmarked`, `bookmarkedKey`) must be `nonisolated` or the build fails ("main actor-isolated ... can not be referenced from a nonisolated context"). Keep any new static session-query helper `nonisolated` too.
- **Apple Developer account not purchased yet** (as of 2026-10-13) — still on free Personal Team signing, 7-day re-sign window. Not a blocker for building/compiling, only for how long an installed build keeps running on-device.
- **Widget deep link is currently dead** since U2 made `HomeView` the app root: `SwipeSessionView`'s `.onOpenURL { deck.date = .now }` only fires while that view is actually mounted (i.e. you already navigated into an On This Day session), so tapping the widget right now just opens to Home with no special routing — not a crash, just a no-op. This is expected and is exactly what U6 (R9, KTD8) fixes by moving the `onOpenURL` handling to `OnThisDayApp.swift` and routing straight into `SwipeSessionView(kind: .onThisDay(.now))`. When doing U6, also delete `SwipeSessionView`'s now-redundant `.onOpenURL` line — leaving it would be dead code per the plan's Definition of Done.
- **Summary-screen trigger condition is `deck.isFinished && deck.marked.isEmpty`, not just `isFinished`.** A card's keep/delete decision is recorded in `history` the instant you swipe it — the asset isn't actually gone from Photos until `deleteMarked()` runs (triggered by the existing "Review N to delete" → Delete flow, which the UI lets you invoke at *any* point once there's at least one pending mark, not only at the end). So right after swiping the last card with pending un-deleted marks, `isFinished` is already true but nothing's been deleted yet — showing the summary there would report 0 deleted and double as a weird gate in front of the Review button. Gating on `marked.isEmpty` too means the summary only appears once any pending deletions have actually been confirmed, whenever that happens relative to "last card swiped."
- **Session-level `deletedCount`/`freedBytes` on `SwipeSession` do not persist across an app relaunch** (unlike `assets`/`history`/`decisions`, which do via KTD2). If a session has a mid-session Review-delete, then the user force-quits before finishing the remaining cards, the eventual summary (after relaunch) will under-report — it won't know about the batch that happened before the restart. Not fixed; flagged as a known, low-stakes gap (solo hobby app, rare timing) rather than engineered around. If it matters later, persist these two fields the same way `PersistedState` already does.
- `project.yml` deliberately leaves `DEVELOPMENT_TEAM` blank so the public repo stays generic/forkable — don't "fix" this by hardcoding a team ID into `project.yml`; that's what `.team-id` + `build-ipa.sh`'s override is for.
- The repo is **public** on GitHub — no secrets, no placeholder junk, code and comments held to the same "exemplary/resume-visible" bar as the existing files.
